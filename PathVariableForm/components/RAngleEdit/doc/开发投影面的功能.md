# 开发投影面的功能

## 1. 功能背景

`PathVariableForm` 同时支持基础模式和高级模式：

- 基础模式通过矩形、圆形等模板生成三维路径线段。
- 高级模式允许用户手动编辑三维线段。
- `Path2dDebugger` 将三维线段转换为二维路径，用于预览、检查和调试。

当前 `Path2dDebugger` 已能识别 `XY`、`XZ`、`YZ` 标准平面，但二维显示中的坐标轴映射和观察方向存在固定规则，用户无法根据实际业务调整。

本功能用于开放二维投影显示规则，使用户能够配置投影面的观察方向和上方向，同时保持基础模式、高级模式与二维显示之间的职责边界清晰。

## 2. 实施阶段

本功能分为两个阶段实施，先完成基础模板三维轮廓生成，再扩展二维调试器的显示方向配置。

### 第一阶段：基础模式按投影面生成轮廓

第一阶段只处理基础模式，不修改高级模式的线段编辑逻辑，也不实现 Debug 区域的前方向和上方向切换。

主要目标：

- 在基础模板编辑器中提供投影面选择：`XZ`、`XY`、`YZ`。
- 矩形模板根据投影面生成对应的三维顶点和线段。
- 圆形模板根据投影面生成对应的三维圆弧和线段。
- 保持圆角、斜切角、表达式计算和模板预览逻辑正常工作。
- 投影面作为基础模板生成轮廓的参数保存和恢复。
- 历史模板没有投影面参数时默认使用 `XZ`。

第一阶段只改变模板生成的三维坐标。例如，当前 `XZ` 逻辑继续保持不变；切换到其他平面时，只改变生成点的坐标轴分布。

第一阶段的验证重点：

- 新建矩形并分别选择 `XZ`、`XY`、`YZ`，确认生成的三维点位于正确平面。
- 编辑宽度、高度、圆角和斜切角，确认轮廓仍然正确生成。
- 新建和编辑圆形模板，确认圆弧所在平面正确。
- 确认保存、取消、重新打开和历史数据兼容。
- 确认现有高级模式行为不受影响。

### 第二阶段：Path2dDebugger 自定义前方向和上方向

第二阶段再处理 Debug 区域的二维显示规则。

主要目标：

- 在 `Path2dDebugger` 中开放投影显示配置。
- 支持用户切换前方向和上方向。
- 根据前方向和上方向重新计算二维横向轴、纵向轴和路径坐标。
- 同步更新路径轮廓、坐标轴、状态栏、标签和包围盒。
- 高级模式和基础模式都只提供三维线段，二维显示由 `Path2dDebugger` 统一处理。

第二阶段不修改基础模板已经生成的三维坐标，投影配置只影响 Debug 区域的显示结果。

## 3. 核心设计结论

投影规则属于 `Path2dDebugger` 的二维显示能力，不属于基础模板或高级线段数据。

基础模式和高级模式只负责生成或编辑三维坐标：

```text
基础模式：模板参数 -> 三维线段
高级模式：手动编辑 -> 三维线段
三维线段 -> Path2dDebugger -> 二维投影显示
```

二维投影配置只影响显示结果，不修改原始三维线段、模板参数或最终保存的路径数据。

## 4. 投影配置职责

`Path2dDebugger` 内部需要维护一套投影显示配置，至少包括：

- 当前投影面：`XY`、`XZ` 或 `YZ`。
- 前方向：表示观察投影平面的方向。
- 上方向：表示二维视图中的向上方向。
- 横向轴：根据前方向和上方向推导。
- 纵向轴：由上方向确定。
- 各轴正负方向：用于处理左右翻转和上下翻转。

建议将投影配置抽象为类似下面的结构：

```ts
interface PathProjectionConfig {
  plane: "XY" | "XZ" | "YZ";
  front: "+X" | "-X" | "+Y" | "-Y" | "+Z" | "-Z";
  up: "+X" | "-X" | "+Y" | "-Y" | "+Z" | "-Z";
}
```

具体的前方向、上方向组合需要进行合法性校验：

- `front` 必须是当前投影面的法线方向。
- `up` 必须位于当前投影面内。
- `front` 与 `up` 必须互相垂直。
- 横向方向由两个方向向量推导，不再额外让用户输入第三个方向。

这里的“前方向”表示从哪个方向观察平面；“上方向”表示该方向在二维界面中朝上。二者会共同决定二维坐标的旋转、翻转和轴标签显示。

## 5. 基础模式与高级模式的边界

### 4.1 基础模式

基础模板可以设置自身的生成平面，用于决定模板三维点落在哪个标准坐标平面：

- 矩形模板根据所选平面生成顶点。
- 圆形模板根据所选平面生成圆弧点和线段。
- 未设置平面的历史模板默认使用 `XZ`，保证旧数据行为不变。

模板的平面设置只负责生成三维坐标，不负责决定二维调试器如何显示。

### 4.2 高级模式

高级模式只保存用户编辑的三维线段。`Path2dDebugger` 根据线段坐标识别其所在的标准平面，或者使用用户指定的二维显示配置进行投影。

高级模式不需要依赖 `RectShape`、`CicleShape` 等模板对象，也不应在高级线段数据中重复保存二维投影规则。

## 6. Path2dDebugger 数据流改造方向

当前逻辑大致为：

```text
segments
  -> buildSegmentModels()
  -> detectProjection()
  -> projectSegmentModels()
  -> 更新二维线段、坐标轴和状态栏
```

后续应扩展为：

```text
segments + projectionConfig
  -> buildSegmentModels()
  -> 确定投影面
  -> 根据 front/up 计算二维坐标
  -> 更新二维线段、坐标轴和状态栏
```

投影转换应集中在 `Path2dDebuggerService`，由 Service 负责：

- 将三维点转换为二维点。
- 根据前方向和上方向计算横纵坐标。
- 处理轴方向正负和视图翻转。
- 返回二维包围盒、中心点和标签位置所需的数据。

`Path2dDebuggerStore` 负责保存响应式投影配置和投影结果；Vue 组件只负责展示配置、接收用户操作和展示状态。

## 7. 自动识别与手动配置

为了兼容当前行为，建议保留自动识别能力：

- 旧数据没有投影配置时，继续根据路径点自动识别 `XY/XZ/YZ`。
- 用户没有手动指定方向时，使用当前默认显示规则。
- 用户主动设置前方向或上方向后，使用手动配置进行二维投影。
- 手动配置只改变二维显示，不改动原始三维路径。

如果后续需要明确区分两种状态，可以增加：

```ts
mode: "auto" | "manual";
```

其中 `auto` 保持现有识别逻辑，`manual` 使用用户指定的投影规则。

## 8. UI 展示方向

投影配置 UI 应放在 `Path2dDebugger` 相关区域，而不是放入 `RAngleEdit` 的模板参数编辑区域。

建议包含：

- 投影面选择。
- 前方向选择。
- 上方向选择。
- 当前二维横向轴和纵向轴的只读提示。
- 非法方向组合的校验提示。

坐标轴覆盖层、状态栏和二维路径必须使用同一份投影配置，避免出现路径已经旋转但坐标轴标签仍显示旧方向的问题。

## 9. 兼容性要求

- 历史矩形数据继续读取旧的 `D` 参数，并在界面中作为“高度”展示。
- 历史模板没有投影字段时默认使用 `XZ`。
- 历史高级模式路径没有投影配置时继续使用 `Path2dDebugger` 当前的自动识别逻辑。
- 不修改已有线段坐标、模板参数、消息名和路径保存结构，除非后续明确决定持久化二维显示配置。
- 二维显示配置如果暂时只属于调试器会话，可以只保存在 `Path2dDebuggerStore`；如果要求重新打开后保持用户选择，再单独设计路径变量级持久化字段。

## 10. 非本次功能范围

- 不修改高级模式线段的业务语义。
- 不把前方向、上方向写入 `RectShape` 或 `CicleShape` 的模板参数。
- 不让二维投影配置反向修改三维坐标。
- 不在 Vue 组件中复制投影计算逻辑。
- 暂不扩展任意斜面或完整三维透视投影；第一阶段只支持标准 `XY/XZ/YZ` 平面。

## 11. 待确认事项

以下内容在编码前需要最终确认：

1. 第一阶段基础模板的“投影面”具体保存字段名称。
2. 第一阶段矩形模板仍使用旧字段 `D` 表示高度，还是同步设计新的高度字段。
3. 第二阶段 `Path2dDebugger` 的投影面是完全由路径自动识别，还是允许用户手动覆盖。
4. 第二阶段前方向和上方向的具体可选组合及默认值。
5. 二维视图的纵向正方向是否统一按“屏幕向下”为正，还是按三维轴正方向显示后再由渲染层转换。
6. 第二阶段用户选择的显示方向是否需要随路径变量保存，还是仅在当前调试器会话中生效。
